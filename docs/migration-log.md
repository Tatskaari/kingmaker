# The migration to one codebase

On 2026-10-17 the repo stopped being two codebases: the prototype (the "Kingmaker V2 PoC", at the root) and the production game beside it in `v2/`. The milestones:

- **M1:** the prototype is dropped, `v2/` is flattened to the root, and the site's `play/` is the game's browser build (below).
- **M2:** the scenes, re-authored as beats on the two-part GM.
- **M3:** the Obsidian plugin authors them.
- **M4:** problem reports.
- Combat later.

Each entry says what changed, where the old thing is in git history, and why where there was a choice. The prototype's last commit is `bc2ab1f`: `git show bc2ab1f:<path>` shows any file of it.

## M1: v2 is the game

### Removed (in history at `bc2ab1f`)

- `src/`: the prototype's code (app, cli, eval, game, llm and lore shims, report, rules, runtime, web, world), with its component READMEs.
- `scenes/`: its 25 TypeScript scenes and their worlds. The game's campaign has the arc's six as data (`campaigns/caerwyn`).

- `tools/v2/` (the converters and recorders that ran the prototype: `scene-files` with its hand-written table of each scene's facts and effects in `scenes/`, `map-files`, `v1-campaign`, `export-vocabulary`, `record-v1-golden`, `record-spell-facts`, `module-engine`, `golden-replies.json`), `tools/record-golden.mts`, `tools/ansi2png.py`, `tools/door-options.ts`, `tools/preview.py`, `tools/sheet.py`.

- `.agents/skills/*` and `.claude/skills` (a link to them): V1-era skills about `packages/`, `scripts/`, `content/` and `AGENTS.md`, none of which is in this repo.

## M2: scenes as beats, played by the two-part GM

### The format in the game (the scenes' foundation)

- **The format's code** is [shared/scene/document.ts](../shared/scene/document.ts) (the types as [scene-format.md](scene-format.md) has them, and a parse that holds a file to its shape and the references the game follows, naming the file and every problem), [load.ts](../shared/scene/load.ts) (`sceneOf`: a file as the runtime's Scene, extended rather than replaced) and [beats.ts](../shared/scene/beats.ts) (where a scene is: `reachedOf`, `stageOf`, `targetsOf`, `openRoutes`, `enteringAt`, `takeRoute`), the same code on both sides. Tested on the hanged clerk ([beats.test.ts](../shared/scene/beats.test.ts), [document.test.ts](../shared/scene/document.test.ts)).
- **GmState** gains `reached` and `twoPart` (roles, notes by turn, `moved`, `held`), kept as gm_state's `reached` and `twoPart` columns; the bindings are regenerated, the AI service's view carries them, and a scene opens with its start reached and as its stage.
- **The campaign is .kmscene files:** `scenes/<id>.kmscene`, read by the simulation's install and its scene defs, the AI service's campaign, the pack and the in-process host, the page's content (the allowlist takes `.kmscene`), the live record and the client's screen fixtures. The old folders (scene.json and Markdown: `git show 779c6b5:campaigns/caerwyn/scenes/<id>/scene.json`), the old loader and `SceneFile`, `RouteFile`, `CastFile` and `SceneInstall` are gone. The campaign check holds every scene to the format's rules (below), and [campaigns/README.md](../campaigns/README.md) says how to write and check a scene.
- **The scenes:** the hanged clerk as committed with the design; the Drowned Rat, the Heron warehouse and the King's morning copied in byte for byte from kingmaker-scratch/v2/m2/scenes, then their integration items in a commit of their own; the two interludes and the talk template converted from their folders by `tools/scene-folders.mts` (in history at `779c6b5`, deleted with the folders since nothing old is left to convert). The format's checker (`validate_kmscene.py`) finds no problems in the seven files.

### Judgement calls

- **The simulation keeps each scene's file whole** in its `scene_def` row (about 330 KB for the campaign), where it kept scene.json's structure without the Markdown before: the two-part GM's commits read words (a person's attitude and the stage's notes, for the roles it gives anyone new), so the simulation needs them. The install holds each file to the format's shape, then loads and validates it as the simulation reads it; SpacetimeDB took the larger install_campaign call in the e2e.
- **The conversion to the runtime's Scene** (load.ts), so the copied GM code keeps working: the start and the beats are its beats, each with the routes that leave it as its transitions and `anytime` empty, as asked; a route's condition is its `when`, and a route into a discovery with no condition reads "The player has come to understand this: <revelation>"; a cue is a cue, a dice route an attempt with its check (success to its target, failure to `onFailure`, its facts on success), anything else an outcome. The format has no words for how a check goes, so a check's success and failure are the stand-in's ("It comes off: <the node's title>."), and it has no reason (a route's label is a title, not "to …"), so the dice line is the roll's alone. Facts are sentences in transitions (the copied code's) and ids in the flat routes and the beats (the format's), with the scene's `facts` to look them up; essentials are the beats with `carry`, their paths' vias in order, each once, as where they're placed, and the cast among them as carriers.
- **The talk template.** The format has one description for the start, where the old template had an opening and a play note: the start's description is the play note then "As the talk opens: …" (scoped, so later turns don't greet again), and the GM's words for a talk's opening change accordingly (town.test.ts expects them). The conversion has a talk rule so the talk plays as it did: its ways into its ending are anytime attempts (the old goodbye was, judged before the reply from either beat), and its way into told is the talk's own (prepareTalk's confided route, worded for each talk), so the template's route there (which the file needs for told to be reachable) isn't a transition. The template has a truth written for it (the checker asks for one) and its goodbye is a good ending.
- **The interludes,** which the story skips: the downtime beat's play note and the opening are the start's description, its pressure the scene's clock (the format's start has no pressure), the old essential `lead` a discovery the story carries, with two paths written for it (Kell's errand, free; the town's gossip, for asking around) and a way in from the start, and Kell's `whyHere` written; `onward` is an outcome now (it was an attempt; it isn't played).
- **The tests of code that plays a scene have a hanged clerk of their own:** [shared/scene/testdata/hanged-clerk.kmscene](../shared/scene/testdata/hanged-clerk.kmscene), the old one in the format (its five beats stages with their old routes, a route of a later beat with an earlier one's id renamed `<id>-<beat>`, self-loops kept, `make-case` a start route, its essentials discoveries nothing leads to, no truth or whyHere), so they don't follow the campaign's content. What the format couldn't carry of it: a check's reason and words, a check's facts on failure, `given`, `essential` and `towards`, an attempt without dice, `make-case` beyond the yard, the yard's pressure.
- **The GM code's tests keep what the goldens were recorded on:** the old hanged clerk as the runtime's Scene with every word (ai/gm/testdata/scenes/hanged-clerk.json, beside the prototype's other scenes) and the vocabulary as it was (ai/gm/testdata/vocabulary.json). The AI service read an installed scene from the campaign anyway; comparing made every edit to a scene's hook, cast or prep fail the check until the vocabulary was written again, which the plugin's authoring (M3) shouldn't need. A file of the wrong shape is held to its shape alone, and the runtime's own validation runs only once the format's rules find nothing, so a problem isn't said twice.
- **Play semantics the design left open:** nothing is open once an ending is reached; `takeRoute` takes the turn too (for `closing` and the path), steps the path (source `post`), marks a carried beat reached as landed (so the boundary owes it no more: "a beat reached is landed"), refuses `failure` for a route without dice, and leaves a failed check with no `onFailure` open to try again. `presentCast` counts the nodes reached as visited.
- **The play semantics' tests are on the hanged clerk,** as asked, but its routes have no dice: the dice test adds two to a copy of it (a check at the cart that fails into the mixed ending, and a climb with nowhere to fail to). The Rat, the Heron and the King's morning have dice routes of their own.

### Judgement calls

- **What moved into shared/ is the per-scene rules, whole.** `sceneProblems` moved as it was, each `p(...)` given its place, and the per-scene part of `storyProblems` beside it. The talk template's rules and the vocabulary's stay in the campaign check: they need every scene's effects and the lore's private entries, or the vocabulary file, and they aren't about the scene being written. The plugin doesn't run them.
- **Where a problem is:** a lore path that isn't there is where it's first named (the scene's lore, its fronts, a person's card, a node); "no good or mixed ending that can be reached" and the runtime's own validation are the scene's; an effect's is its ending's (onEnd's and afterwards' are the scene's fields).
- **Four loop variables in shared/world are annotated `Entity | undefined`.** The plugin type-checks the shared code it imports under its own compiler options (TypeScript 5.9, no `noUncheckedIndexedAccess`), which read `world.entities[id]` as never undefined, and then refused the loops' `undefined`. Annotating them is what they always were; the alternatives were the plugin moving to the game's TypeScript and options (every index of its own code to revisit) or a hand-written declaration file for the shared types (two copies of the contract).
- **Byte for byte by never rebuilding the file.** Every scene of the campaign (and the tests' clerk) is exactly `JSON.stringify(scene, null, 2)` and a newline, so the plugin keeps the parsed object and changes one value at a time: an existing key stays where it is, unknown keys too, and a key that's new goes where the format and the campaign's files order it (the orders are in [model.ts](../tools/authoring/src/scene/model.ts), taken from the seven files; a key the order doesn't know stays after the key it followed). An optional field emptied is taken out of the file (a check unticked, requires all cleared, a fear deleted), so the file reads as one written by hand; a required one (a look, `knows`, a node's `lore`) stays, empty, for the problems to name.
- **Never a file the game can't load.** An edit whose result fails the game's shape check is refused with a note rather than saved, and the removals take what named the removed thing with them: a node takes its routes, the requires and on-failures that name it and the arrivals at it; a fact takes every beat's and route's establishes of it; a person takes the start's and events' notes for them. What the shape check allows but the rules don't (a path via someone removed, an effect naming them) stays, for the problems panel to name.
- **Ids are asked for once and shown after.** A new node's title is asked for in the add dialog (with an optional id), so its id is a slug of a real title rather than of "New discovery"; a person's id is asked for with their name (it should be short, like `kell`); a route's id is made from where it goes (`find-<discovery>`, `to-<node>`); a slug drops accents and apostrophes and keeps 48 characters. There's no renaming of an id afterwards: game state keys on them, and the format says never to rename a played scene's. A group member's id can be edited, as a slug.
- **New nodes and routes:** a discovery starts with an empty revelation and no paths, an event with nothing but its title, an ending as a good progress ending (the author grades it); a new route is a cue into an event (the authoring guide's way to an event) and an outcome otherwise, with no dice and the campaign's DC of 12 beside it. With a node selected, a new node comes with a route from it, as in the old editor.
- **Grouped routes work as the old editor's connections did:** one connection on the graph for the routes from one node to another, each route its own in the inspector, added and removed one at a time, deleted together, and moved together to other ends. A moved route keeps its id, even one made from where it went (`find-murder` moved elsewhere): the id is a name the game keys on, not a description.
- **A new scene's skeleton** is a start, a discovery and an ending (ids `start`, `discovery` and `ending`, slugs of their titles) and one route, from the start into the discovery: the format's smallest graph with each kind. Its file is named for the slug of the title, which is the scene's id (the campaign check's rule), and the problems panel lists the thirteen things left to write. It isn't added to campaign.json (the panel says the game won't install it until it's listed): which scenes a campaign has is the scenario's to say, and M4 brings the scenario to the campaign's files.
- **Which files are version 1:** a `.kmscene` with `format: "kingmaker"`, `version: 1` and `kind: "scene"` opens read-only, with its title and size and a note. Anything else that isn't a scene of the format (a version 1 scenario in a `.kmscene`, a version 2 file with a dangling route) opens as an error naming each problem, as before.
- **The old editors and the new files.** The scenario editor reads the vault's files as version 1 graphs: a version 2 scene is listed as one it doesn't read, and an open version 2 or read-only version 1 scene isn't an editor it can update in place (a port edit to a version 1 scene writes the file, which the read-only view then reloads). Its "Create new scene file" now makes a version 2 skeleton, which it can't wire. Making it read version 2 is M4's work.
- **The vault's shared settings** are two files: `.obsidian/app.json`, setting where a new note goes (`lore/`: a note made by following a link, or by hand, belongs with the GM's docs, not at the campaign's root beside campaign.json), and `community-plugins.json`, with the plugin on. Everything else is personal and ignored by an allowlist in campaigns/caerwyn/.gitignore: the workspace files and the cache as asked, but also the installed plugin (build output), appearance, hotkeys, the graph view and `core-plugins.json` (it carries choices like Sync, which is an account's). No attachment folder is set: see Open.
- **The installer adds no files to the vault** beyond the plugin's own. Its example files would have been files of the campaign, and on a case-insensitive file system the example's `Scenes/` folder is the campaign's `scenes/`.
- **The lore the plugin offers** is every note under `lore/`, but of each person's folder only their public card (their private notes, GM notes and memories are what the game keeps for them). A note's name is its folder's for a public card (`Cob`), else its file's; its kind is its top folder's (Cast, Places, World, other). The rules check a lore path against every file under `lore/`, as the campaign check does.
- **A scene's campaign** is the folder its `scenes/` folder is in, so the plugin works with the campaign folder as the vault (as set up) or with a folder above it, a whole checkout say. Its campaign.json, places and other scenes are read through Obsidian's vault (an open editor's unsaved draft standing for its file), again a moment after any file changes.
- **A path's via** is offered from the cast (their ids) and the place's things and areas by their names, since a via of one word must be a cast id and the things' ids are one word; anything typed is kept. A carried discovery's things are the place's and those another scene carries.
- **Effects:** forms for the story's seven ops, their fields in the orders the campaign's files have them, and the conditions as checklists of the scene's facts (one fact written as its id, several as a list, as the files do); changing an effect's op makes a fresh one of the new op, keeping its conditions. Any other op is JSON, saved once it parses as an object with an op; a new world op of afterwards stays a draft until it also names what it acts on (the shape check requires it).
- **Cast notes:** the start offers a note for each person there at the start (and keeps any other's), an event for everyone. An event's "who arrives here" is each person's `enters`, so ticking someone moves them from another event.
- **React Flow and the problems.** The graph keeps a node's object unless what it shows has changed: React Flow keeps a node's measured handles by its identity, and the campaign's late answer (and the problems computed from it) replacing every node lost them, so a scene opened right after another sometimes drew no edges (the talk template did, in the test that opens every scene). The problems are computed from a deferred copy of the scene, so typing doesn't wait on them.
- **The harness and the tests.** The browser harness's vault is the real campaign folder's campaign.json, places, scenes and lore (`KINGMAKER_CAMPAIGN` names another, in place of `KINGMAKER_LORE_ROOT`), opening on `scenes/hanged-clerk.kmscene`. The old editor's journeys went with it; the scenario journeys keep their own version 1 seeds in scenario-journeys.spec.ts, but for one that opened the old vault's `Places/Granary Yard.md` from the example scenario (the lore is under `lore/` now, and the scenario is M4's). The host tests run the save machinery (conflicts, echoes, late callbacks) on version 2 scenes and the scenario's port edits on maps, its own files; they bundle plugin.tsx with esbuild now, since it imports the game's shared code, with `./App` stood in for as before.
- **The bundle check is a Playwright test,** loading `dist/plugin/main.js` (or a vault's installed copy) as Obsidian loads a plugin, CommonJS with the `obsidian` module given, in a page: the bundle carries React DOM, which needs a real DOM, and the host tests' Node has none (jsdom isn't a dependency). Its mock of Obsidian's API is the host tests' in kind.
- **The plugin's version is 0.9.0,** its description the game's scenes in the campaign folder; the package keeps its name.

#### Judgement calls

- **The inspector is the Graph's.** The other views take the whole main area, without it: the selection is on the graph, and a half-screen pane hasn't room for a view and an inspector. Narrower than 760px the inspector lies over the graph's right side, and only while something is selected (empty, it hid the nodes it asked you to click). Sizes follow the editor's own width with container queries, not the window's with media queries, since an Obsidian pane is narrower than its window.
- **Remembered per file, for the session.** The view (and the graph's pan and zoom, since the graph is unmounted while another view is open) is kept for the file's path while the plugin is loaded: reopening the file, or the editor being remade by a change from outside, comes back to it. - **Ids renamed, by asking.** M3 had ids made once and never renamed, since game state keys on them. The user's principle (no value the tool sets that the author can't change) and the fact renames they asked for reverse that: a node's, route's, person's, fact's and the scene's id has Rename, which checks for a free slug and warns that a game already played loses track of the old one; everything in the file naming it follows in one edit (a node: its routes' ends, requires, on-failures and arrivals; a person: the roles keyed by them in their places, the paths via them, the effects naming them, the talk's companion; a fact: establishes and conditions). The scene's own id is changed in the file and not the file's name, which Obsidian renames: the problems say until they agree.

It asks first when it would take something out. An ending stays an ending: it has different fields and no routes out, and it's simpler to add another.
- **Values a kind doesn't use** are shown only where a file has them, offering to take them out, never to add them: an event's paths (the rules refuse them) or required mark, a discovery's pressure and roles.
- **Effects:** a form for every op the format has, each with the fields the world's ops read (from `applyOps`: what, to, how, feet, name, kind, text, the states added and removed, quantity) or a fight's set-up (enemies, allies, at); keys a form doesn't show are named under it, and JSON edits the whole effect. - **The cast card says where the scene uses someone** (arrival, roles, paths via them, effects naming them), each a link: not asked for, but it's the facts' "where it's used" for people, and it's where an author renaming or removing someone looks.

- **A fight's allies and where it breaks out couldn't be left out:** a new Start a fight was written with `"allies": []` and `"at": ""` (which the rules then named as a place that isn't there), and neither could be taken out but by its JSON, though both are optional. A new one is only its enemies; allies emptied, or the place, are taken out.
- **An effect that would do nothing passed every rule.** An effect added as a form starts with its target empty (a give, a note, a move), and one left that way was saved and did nothing in play, with nothing telling the author. The shared rules ([rules.ts](../shared/scene/rules.ts), so the campaign check too) now say a world op names what it acts on (a create, what it makes) and a flag has a name; the scene format's list of rules says so.
- **An ending couldn't be sent to a scene still being written.** Next scene (and Overtaken) offered campaign.json's scenes only, so the first thing an author does with a new scene, sending the story to it from another scene's ending, couldn't be done in the tool until they'd listed it in campaign.json by hand, and nothing said why it wasn't offered. The scene files of the campaign's `scenes/` it doesn't list yet are now offered after its scenes, each saying so, and the problems say so until it's listed.
- **The Scene view's Rest and Milestone** said "A rest before it" and "A milestone of the story"; they now say what the game does with them (time passing before it opens; the character going up a level as it opens).
- **The harness had no way to begin a scene:** it now has a New scene button doing what Obsidian's New Kingmaker scene does, and `tests/new-scene.spec.ts` writes the Short Weight (shortened) through the UI as above, finds no problems, and sends the clerk's failed ending on to it.

#### Judgement calls (the author's pass)

- **Where a new card goes:** straight below where it's wanted, not the nearest free spot in any direction, so a node's new neighbours stack in a column beside it, as an author lays a graph out by hand.
- **Only a label that's still the default follows a retitle,** compared exactly with what a new route into that node would have been given from its old title: anything typed is the author's. Route ids don't follow (game state keys on them; Rename is there).
- **A kind change is a whole change, not a conversion.** A beat made an ending isn't kept "as it was" in case it comes back: what it loses goes from the file (undo brings it back), and the question names it first. The start stays the start, as a scene has exactly one.
- **The narrow pane keeps the inspector over the graph** rather than moving it below: a graph flows left to right, so a panel below hides as much as one beside, and the overlay is put away with a click on the graph's background. What changed is that it never hides what it's about, nor what's being drawn to. The quarter-second before it shows is a double-click's span, in both the CSS and the editor (a constant each, said beside the other).
- **The minimap goes at 1000px and under** (where the inspector beside the graph narrows it to about 670px), not only in the narrowest panes: at that width it covered cards at a fitted graph's edge, and the zoom controls and F remain.
- **A new rule in the game's shared rules** rather than a warning of the plugin's own: an effect that does nothing is as wrong in a file written by hand, and the campaign check should refuse it too. It's narrow (the world ops' target, a create's name, a flag's name), and every scene of the campaign keeps it.
- **Unlisted scenes are offered, not hidden,** with the problem saying so, rather than the editor writing campaign.json: campaign.json is the scenario's (M4), and listing a scene installs it in the game, which is the author's call.
- **Not changed:** the order of the cast, the facts and the lore links in the file, which the editor doesn't offer to change (an order rather than a value: new ones go last, and the talk template's companion-first is its own rule; up and down for people would be the next thing if an author wants the GM to meet them in another order); a world op in an ending stays a card from the moment it's added (the problems say what it lacks) rather than a draft as afterwards' are, which the format needs there.
