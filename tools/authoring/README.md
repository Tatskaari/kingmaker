# Kingmaker Authoring: the game's campaign in Obsidian

An Obsidian plugin for writing the game's campaign. Its vault is the campaign folder itself, [campaigns/caerwyn](../../campaigns/caerwyn/), and it edits the game's own files there, as the game loads them: the scenes (`scenes/<id>.kmscene`, the scene format: [docs/scene-format.md](../../docs/scene-format.md)), and the scenario, its maps and its places (`caerwyn.kmscenario`, `maps/<id>.kmmap`, `places/<key>.kmplace`, the scenario format: [docs/scenario-format.md](../../docs/scenario-format.md)), every one version 2. There's no export: the game loads the file the plugin saves, as it is, and the plugin holds each file to the same rules as `npm run campaign -- check` while you write. The lore is the vault's Markdown, edited in Obsidian's own editor.

The plugin's own version 1 files (its old scene graphs, scenarios and maps) aren't the game's: a version 1 scene or scenario opens read-only, and a version 1 map opens with the offer to migrate it.

## Setting up the vault

```sh
cd tools/authoring
npm ci
npm run build
npm run install:vault -- ../../campaigns/caerwyn
```

Then in Obsidian: **Open folder as vault**, and choose `campaigns/caerwyn` in your checkout. If Restricted mode is on, allow community plugins in Settings → Community plugins; Kingmaker Authoring is already in the vault's list of enabled plugins. Open `caerwyn.kmscenario` for the story's flow, `scenes/hanged-clerk.kmscene` for the worked example of a scene, or `maps/caerwyn.kmmap` for the town, from the file explorer (or the ribbon icon, or **Kingmaker Authoring: Open scene, scenario, map or place**).

`install:vault` copies `main.js`, `styles.css` and `manifest.json` into the vault's `.obsidian/plugins/kingmaker-authoring/` (the files it replaces are backed up under `dist/install-backups/`) and adds the plugin to `.obsidian/community-plugins.json`. It writes nothing else. Run it again after `npm run build` to update the plugin, and reload Obsidian.

What's shared and what's yours: the vault's `.obsidian/app.json` (a new note goes in `lore/`) and `community-plugins.json` (the plugin is on) are the campaign's, in git. Everything else Obsidian keeps in `.obsidian` (the workspace, the cache, the installed plugin itself, appearance, hotkeys, the core plugins) and the `.trash` folder are each author's own, and [campaigns/caerwyn/.gitignore](../../campaigns/caerwyn/.gitignore) keeps them out of git. The game never reads them: the campaign check, the install and the web build all leave hidden files out.

In the vault you see the campaign as the game has it: `arc.md`, the scenario (`caerwyn.kmscenario`), the scenes in `scenes/`, the maps in `maps/`, the places in `places/`, and the lore in `lore/` (the world, the places, and each person's public and private notes). Each of the game's files opens in its editor. The JSON files (`builds.json`, `looks.json`, `vocabulary.json`) are there too, hidden from Obsidian's file explorer unless you turn on Settings → Files and links → Detect all file extensions; they aren't authored in the plugin yet.

### Moving from the old vault

Until now the plugin was installed in your checkout's `lore/` folder, the prototype's copy of the lore, with the imported version 1 scenes, the scenario and the maps. That vault is left as it is. To move:

1. Install the plugin into the campaign folder and open it as a vault (above). Your own settings (theme, hotkeys, open tabs) don't come with it: set them again, or copy `appearance.json` and `hotkeys.json` from the old vault's `.obsidian/` into the new one's (they're ignored by git there).
2. Your version 1 draft of the clerk, `Scenes/The Hanged Clerk v2.kmscene`, became the game's `campaigns/caerwyn/scenes/hanged-clerk.kmscene`: M2 re-authored it in the scene format as the worked example (its start, its three discoveries, the dead-cart and its three graded endings), so edit that one.
3. The old vault's other version 1 scenes (the imported `Scenes/*.kmscene`) were snapshots of the prototype's scenes. If the new plugin is installed there, they open read-only, with a note that the format has moved on: the campaign's own scenes are in `scenes/` of the new vault.
4. The old vault's scenario (`Scenarios/Caerwyn.kmscenario`) is a version 1 file: it opens read-only. The campaign's scenario is the new vault's `caerwyn.kmscenario`. The old vault's maps (`Maps/*.kmmap`) are version 1 maps: copy one into the new vault's `maps/`, named for its id (`maps/harbour-study.kmmap`), open it, and migrate it (below).
5. The old vault's lore notes are the prototype's copy. The game's lore is the new vault's `lore/`, which M1 brought up to date with the prototype's last edits.

## The scene editor

A scene file opens with its title, a line under it saying how many problems it has, and warnings (click it for the Problems view), and a bar of views: **Graph**, **Scene**, **Cast**, **Facts** and **Problems**. The Graph has the scene's nodes and routes, with an inspector beside it for whatever is selected on it; the other four are the scene's own, each in the main area. The bar is keyboard-reachable (Tab to it, then the arrow keys, Home and End), and the view you're on is remembered for the file while it's open (open another file and come back, and you're where you were; the graph keeps its pan and zoom too). The editor follows its pane's width rather than the window's: from a half-screen pane up the inspector sits beside the graph, and narrower (under 760px) it lies over the graph's right side while something is selected. Then a node you click where the inspector will lie slides into the strip of graph beside it (a moment after the click, so a double-click still opens its larger editor, the roomiest in a narrow pane), a node shown from a problem or a link is centred in that strip, and a fit fits the graph into it; while a route is being drawn the inspector stands aside, so the node it goes to can be clicked wherever it is; and a click on the graph's background puts it away. The minimap is put away in panes 1000px wide and under, where it would cover the graph's cards, and the Cast view's list goes above the card in a narrow one.

### The graph

- **The kinds, at a glance.**
  - The **start** (green) is where the scene opens: one in every scene, with how many people are here at the start.
  - A **discovery** (purple) is a beat with a revelation, something the player can come to understand. Its card counts its paths and marks a **required** one.
  - An **event** (amber, dashed) is a beat without one, a turn the scene takes. Its card names who arrives there.
  - An **ending** (red) is one of the only ways the scene can end. Its card shows its result (good, mixed or bad), its exit kind, and the scene the story goes on to. The result's badge is a button: it opens the ending with its result chosen, to change it.
- **Routes.** The routes from one node to another are one connection on the graph, labelled with the route's name or "n routes", dashed when they're cues, and marked "dice" when one has a roll. Click a connection to see each of its routes in the inspector, each its own.
- **Adding.** **A** (or **Add node**) adds a discovery, an event or an ending: you give its title, and its id is a slug of that title, free in the scene (or one you type). With a node selected, a route from it comes too, and the new node goes beside it (below any cards already there, never on one). Draw a route by dragging from a node's right edge to another node's left edge, or with **Add route to…** in a node's inspector. A new route's id is made from where it goes (`find-murder` into a discovery, `to-cart-arrives` otherwise); into an event it's a cue.
- **What a new one starts as** is shown, and every part of it changeable: a discovery has an empty revelation and no paths; an event only its title; an ending is a good progress ending (its result and exit kind are at the top of its inspector); a route has no condition and no roll (the file keeps a DC of 12 beside it, used once it has a roll), and its label is made from the title of the node it goes to ("Find <title>" into a discovery, the title otherwise), following that title when it's changed until you write the label yourself.
- **Deleting** asks first. A node takes its routes with it, and what named it: a route's requires and its on failure, a cue's outer limit counting from or until it (a count after it goes), and who arrived there. The start can't be deleted.
- **Undo and redo** (Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, or the arrows on the bar) last while the file is open, in every view; typing in one field, from its focus to its blur, is one step. **F** fits the graph, **?** lists the shortcuts, and a double-click opens a node's or a connection's larger editor. **A**, **F** and **Delete** are the graph's, and do nothing in the other views.

### The inspector: what's selected, and its + add flows

The inspector is only ever what's selected on the graph: a node, or a connection's routes. With nothing selected it says so (in a narrow pane it gets out of the way). Every list in it works the same way: what's there as cards or chips, each removable (and the cards that have an order, paths and effects, moved up and down), and a **[+ Add …]** button that opens a short list to pick from in place, searchable when it's long, with Esc to close it. An optional part is a [+ Add …] button until it's there, then a section with a remove button; a text that's optional, emptied and left, is taken out of the file.

- **Every node:** its **id**, with **Rename** (a slug, not taken; renaming asks, and everything in the file naming it follows: its routes' ends, what requires it, where a failed roll goes, what a cue's outer limit counts from and until, who arrives there), its title, its **lore** (link and unlink notes), its routes in and out, **Add route to…** and **Delete node**.
- **The start:** its opening, and its **conversation roles**: a card for each person with a role as the scene opens (their note, the co-GM's first), and **[+ Add role]** to give one to anyone else of the cast. A role is written once it has words.
- **A discovery:** **Required**, its revelation, how to play it, its **paths** (cards, each with who or what holds it, typed or picked with **Pick via** from the cast and the place's things and parts (each named with its id), and a note under it when it names neither someone of the cast nor a thing of the place; the clue; what earns it; its strength, one of hook, suggestive, strong or proof, with a line on each; and **[+ Add a roll]** for a skill and a DC when a roll suits it), the **facts settled here** (**[+ Add fact]**), and **[+ The story carries it]** (what it unlocks, what later needs it, and the things of the place it's in, **[+ Add thing]**).
- **An event:** what happens; **[+ Add pressure]** (what the world does if the scene stalls here: a section, removable); **who arrives here**, as chips (**[+ Add person]** picks someone of the cast: one who arrives at another event says so, and moves here; removed, they're here from the start); **conversation roles here**, as at the start (only the people with a role are listed); the facts settled here; and the story carrying it.
- **Its kind:** every node but the start is a discovery, an event or an ending, chosen at the top of its inspector. A discovery made an event loses its revelation, paths and required mark; an event made a discovery loses its pressure, its roles and its arrivals (it's never the stage). A beat made an ending loses all that a beat has (and the facts it settles and what the story carries), and with it its routes out (none leaves an ending), what required it (only a beat is required), what a cue's outer limit counted of it (only a beat is counted from or until) and who arrived there; it's a good progress ending to start with. An ending made a beat loses its closing, result, exit kind, next scene and effects. Each asks first, naming what goes, when it would take out something you wrote.
- **An ending:** its **result** at the top (Good, Mixed or Bad, with a line on what each means for the story and for QA) and its **exit kind** (each in full: combat ends in a fight played out on the map; the others are labels the effects give meaning to); what's true; its closing; the next scene (one of the scenario's, or a scene file of its `scenes/` that the scenario doesn't list yet, which the problems name until it's listed, or nowhere; and a link to open it); its **effects**; and its ways in, each with what it requires.
- **A connection:** each route's **id** (Rename), label, condition, **phase** (Outcome or Cue, with a line on each), **requires** as chips (**[+ Add beat]**: the beats reached first, an ending's evidence), **[+ Add a roll]** (a skill, a DC, and where a failure goes; removing the roll takes the failure with it), the facts settled when it's taken, and a cue's **[+ Add an outer limit]**: its counts, each so many exchanges from the scene's start or from a beat reached and until beats, the cue overdue once one still running runs out (an outcome's limit is shown only to take out). Add another route between the same two nodes, or remove one, and the others stay; **Move these routes** gives all of them another node to leave from or go to, their ids kept.
- **Effects** (an ending's, and in the Scene view the scene's as it starts and on every ending) are cards, in order, each a form for its op: the story's (quest, flag, attitude, remember, journal, follow, promise), the world's (move, place, give, drop, create, state, note, forget, remove, destroy, break, ignite, douse, chill, bleed, spill: what it acts on, picked from the cast, the place's things and parts or typed, and the fields that op has) and a fight's set-up (startFight: its enemies, and its allies and where when it has them). **[+ Add effect]** lists every op with a line on it. Each effect's **condition** is under "When": **[+ Only if a fact is settled]** and **[+ Unless a fact is settled]**, each picked from the scene's facts or a new one made there (one fact is written as its id, several as a list, none as no condition). Changing an effect's op keeps what the two share (who, what, the text) and its conditions. Anything a form doesn't show is named under it; **Edit as JSON** edits the whole effect, kept only once it's whole, and an op there's no form for (one the story doesn't know yet) is JSON. An effect that would do nothing (a world op that doesn't say what it acts on, a create that doesn't name what it makes, a flag without a name) is a problem until it does.

### The Scene view

The scene's own fields, grouped as an author thinks of them, each group a card (and a row of links at the top to jump to one):

- **The scene:** its title, its **id** (its file's name: Rename asks, and says to rename the file to match, since the scenario and the endings that go on to it name it too; the problems say until they agree) and its one-line description.
- **What the player knows:** the hook.
- **The prep:** setting, premise, truth and clock.
- **When and where:** time, place (one of the campaign's, with the place's things listed under it and a button to open the place), rest, interlude, milestone and whether it comes to the player.
- **The world:** limits and what locals know, each a list.
- **The story:** background, assumes, overtaken, the effects **as it starts** (onStart: effect cards with conditions, as an ending's: what the scene does once as it comes into the story, before it's played, as the lead the player is heading for on the map or as it opens with none; the hanged clerk starts its quest there, with the King's request), the effects **on every ending** (onEnd: effect cards with conditions, as an ending's), **afterwards** (the world ops applied to the place as it ends, whatever the ending: world op cards without conditions; a new one is a draft until it says what it acts on, and is saved, in the same card, the moment it does), the fronts doc, and the talk template's companion.
- **Lore:** the GM's always-in docs.

### The Cast view

The people of the scene in a list (each with what the player calls them, their id and where they arrive), beside the chosen person's card, roomy, with every field of one: who they are (name, called, also known as, their lore note), how they come across (look, voice, attitude), what drives them (wants, fears, why here), what they know (knows, secrets), playing them (the roles palette: characterise, inconsistency, hooks; and limits), and in the scene (enters, group, members, statblock, weapon). Above the fields, **In this scene** says where the scene uses them: where they arrive, the nodes where they have a conversation role, the paths via them and the effects naming them, each a link there. Their **id** has Rename (the roles, paths and effects naming them follow; the place's people and looks.json name them too, which the problems say). **[+ Add person]** asks a name and an id (a slug; short, like `kell`).

### The Facts view

A fact is a sentence the GM is told once it's settled: a beat settles it when it's reached, a route when it's taken (a roll's on a success), and an ending's effects test it. The Facts view lists each fact with its id, its sentence (edited there), **settled by** (each beat or route, a link that selects it on the graph with its facts focused) and **tested by** (each effect, only if or unless, a link that opens it). **[+ Add fact]** makes one: its sentence, and an id that's a slug of it unless you type one. A fact can also be made in place from any [+ Add fact] (a beat's, a route's) or an effect's condition, and is settled or tested there in the same step of undo. **Rename** gives a fact a new id, and every establishes and condition naming it follows. Removing one asks, saying what settles and tests it, and takes it out of every establishes and condition (a condition left with no fact goes: an effect that ran only if it was settled runs whatever happens).

### The Problems view

The game's own rules for a scene ([shared/scene/rules.ts](../../shared/scene/rules.ts), what the campaign check runs), run as you edit against the campaign around the file. Each problem says where it is, down to the field ("Node · Failed · Closing", "Route · Last resort · Condition", "Cast · Corporal Abner Tull · Why here"), and clicking it takes you there with the field focused: the node or route selected on the graph, the person's card in the Cast view, the fact in the Facts view, or the field in the Scene view. It also says when the scene isn't one of the scenario's scenes yet (`caerwyn.kmscenario`'s `scenes`: the game doesn't install it until it's listed). The talk template (the scenario's `talk`) is held to the talk's own rules too (its companion `{companion}`, the start's opening role for them, the discovery `told` each talk's prep fills, a way into `goodbye` from the start, no place), and its `told` says in its inspector that each talk fills its words. Below the problems, and not counted with them in the view's count, are the **warnings**: each clue path whose via, of more than one word, names neither someone of the cast (by id, name, what they're called or also known as) nor a thing or part of the scene's place (by id or name, as words: no case, no leading article, nothing in brackets). The game takes a via as words, so it isn't a problem; but the GM is told the clue is with something the scene hasn't got. Each takes you to its discovery, and the line under the scene's title counts them beside the problems ("No problems · 3 warnings").

### Lore

Lore paths in a scene are the game's: relative to the campaign's `lore/` (`Cast/Cob/public.md` is the vault's `lore/Cast/Cob/public.md`). The plugin offers the campaign's notes that way (each person's public card once, the places, the world and the rest; a person's private notes and memories are the game's), and a link opens the note in Obsidian's own editor. A scene can link lore for itself, for each node, for each person (their card) and its fronts doc. Obsidian doesn't rewrite these paths when a note is renamed or moved: the Problems view names a link whose note isn't there.

### A new scene

Right-click a folder (the campaign's `scenes/`) for **New Kingmaker scene**, or run **Kingmaker Authoring: Create new scene**. Give it a title: its file is named for the slug of the title, which is its id (`The Lamplighter` is `scenes/the-lamplighter.kmscene`). It starts as a skeleton: a start, a discovery and an ending, and a route from the start into the discovery, with the Problems view listing what's left to write. Retitle or rename its placeholders as you write them (the route into the discovery takes the discovery's new title). List its id in the scenario's `scenes` (`caerwyn.kmscenario`) for the game to install it: the scenario editor's Files view lists it, or makes the scene and lists it at once, as does every picker of a scene in the scenario and map editors (New scene). The browser test harness has a **New scene** button that makes one as the command does. **New Kingmaker map** and **New Kingmaker place** work the same way (in `maps/` and `places/`: a map from the default legend on grass, a place of one area), and **New Kingmaker scenario** makes a campaign folder's scenario, refused where there's one already.

## The scenario, map and place editors

They follow the scene editor's design, and the same rules: every value of the file is created, changed and taken out in the editor, where an author would look first; the right-hand panel is the inspector of what's selected on the canvas, and nothing else; the file's own fields are views of their own in the main area, on a bar under its title (Tab to it, then the arrow keys, Home and End; the view is remembered for the file while it's open); lists are a list beside the chosen item's card, or cards and chips, each removable, with a **[+ Add …]**; an optional part is a **[+ …]** until it's there; and where one file names another (a region's scene, an exit's map, a scene's place) it's shown both ways, and a new one can be made where it's picked: made from its skeleton, listed in the scenario and picked, as one step of undo (the file stays when the step is undone). Under the title, a line says how many problems the campaign check would find (click it for the Problems view). In a pane 1000px wide or less the inspector narrows; at 760px or less it lies over the canvas's right side while something is selected, and what's selected slides into the strip beside it (on the scenario's diagram a moment after the click, so a double-click still opens the file).

## The scenario editor

`caerwyn.kmscenario` opens with a bar of views: **Diagram**, **Scenario**, **Files**, **Quests** and **Problems**.

- **The Diagram** is the story: the start, the scenario's scenes (along the top, in the story's order) and its maps (beneath them), each a card, with the inspector beside it for the card or the way out selected. The flow is the files': nothing of it is stored in the scenario, and each edge is drawn from the file that owns it and edited there.
  - A scene's card has a port for each of its endings, whose edge goes to its `next` (in the scene's file).
  - A map's card has a port for each region that plays a scene (`sceneId`, in the map's file: solid when the region lays the scene's place, dashed when it opens a scene laid elsewhere) and for its ways out, grouped by where they lead and what they say (the town's four tiles along the wharf to the Heron are one port, its exits in the map's file).
  - The start has two: the map the player starts walking on (`start.map` and `start.at`) and the first lead (`firstScene`), in the scenario.
- **Wiring.** Drag from a port's handle to a card, or click a port, an edge or a card and choose in the inspector: an ending's next scene, a region's scene (every region of a map is listed, not only those that play one), a way out's map (it lands just inside the target map's way back, or nearest its middle: the tile is in the inspector, or the map), the start's map. Each picker has **New scene** (or **New map**) under it: the file is made, listed in the scenario and wired in one step. Taking a destination away (the Delete key on an edge, or the inspector's own choice for it) asks first, but for an ending set to go nowhere in its select: an ending then ends the story, a region stops playing its scene, a way out is deleted, and the start without a map opens the first scene at once.
- **Writes are safe.** An edit of another file is refused, with nothing overwritten, unless that file is what the editor read: on disk, or in an editor that has it open, which is given the new text as if it changed outside it. Undo (Ctrl/Cmd+Z) writes each file back the same way.
- **The layout** is the scenario's own `layout` (nothing the game reads): a card dragged keeps its place, by `scenes/<id>`, `maps/<id>` or `start`, and a card that has none goes where the default puts it. **Forget the layout** (the eraser on the bar, on the Diagram) puts every card back, after asking. The diagram keeps its pan and zoom while another view is shown, and brings a new scene's or map's card into view when it's next shown.
- **The Scenario view** has the scenario's own fields, in groups: **the campaign** (its title, its id, renamed by asking: it's the file's name and the id games are installed by, and the problems say until the file is renamed to match; its description, campaign version, level and rules pack; and any key the format doesn't have, shown to edit or take out); **the start** (the first scene, the start place, the day and time, the start map and tile; each of the first three can be a new file, made and picked in one step); **the starting purse** (a card a coin: its name, how many, and what it is; moved and removed; **[+ Add coin]**); and **the world a backstory is written for** (its name, premise and primer; the docs that aren't canon as chips, each picked from the lore with **[+ Add a doc]**; and the places a backstory can call up, each a card with its doc and the words that call it up, **[+ Add a place doc]**).
- **The Files view** lists the scenario's scenes (in the story's order: moved up and down), the talk template, the maps and the places, each a card that opens its file and says where the campaign's other files name it: a scene, the regions that play it (laying its place or opening it), the endings that go on to it (and whether it's the first lead), its endings' next scenes and its place; a map, its size, where its ways out go, the ways in from other maps, and the regions that play a scene; a place, the scenes played in it and the regions that lay it. **[+ Add scene]** (or map, or place) lists one of the folder's files the scenario doesn't list yet, or makes a new one there; the bin takes one out of the scenario after asking (its file stays). The talk template is one of the folder's scene files that isn't one of the story's, or a new one.
- **The Quests view** has a card for each quest: its title, its key (renamed by asking: every scene's quest effect naming it follows, in its own file, in the same step: an ending's, and the scene's as it starts and on every ending) and the effects that name it, each a link to its scene (the hanged clerk's quest first by what the clerk starts as it comes into the story). **[+ Add quest]** asks a title and a key, a slug of the title unless one's typed; removing one asks, saying which effects name it.
- **The Problems view** is the campaign check's rules for the scenario, its maps and its places ([shared/scene/scenario-rules.ts](../../shared/scene/scenario-rules.ts)), with every file as it is now; each takes you to its field in the view that has it, or opens its file.

## The map editor

A map (`maps/<id>.kmmap`) opens with a bar of views: **Paint**, **Preview**, **Map**, **Legend**, **Regions**, **Exits**, **People** and **Problems**.

- **Paint** is the isometric painter: the palette on the left (the map's legend), the map in the middle, and the inspector on the right for what's selected: a tile, a region, an exit, someone about, a legend entry, the story's start, or a part of a scene's place laid on the map.
  - **Painting.** The palette is the map's legend: each entry its character, a swatch in the game's colours for its terrain and look, its name, and how many tiles it covers. Paint with the brush (**B**), rectangle (**R**) and fill (**G**), erase (**E**) with the Erase material (Ctrl/Cmd-drag too), sample with the eyedropper (**I**), pan (**H**), and **[ ]** size the brush; **X** swaps the paint and erase materials. The void (no tile) is painted like any entry. Only the rows a stroke changes are written, each its own length where what's past it is void, so a painted map's file changes where it was painted and nowhere else. In a narrow pane the palette is its swatches and characters, and the tools their icons.
  - **Select** (**V**) and click a tile: the inspector says what the tile is painted with (to edit the entry or paint with it), what stands on it (each to select), and what can be added there: a region, an exit, someone about, the story's start, and when a scene's place is laid there a thing, an area or someone of the scene. A right-click on any tile is a menu of the same.
  - **Regions** are drawn with the region tool (**N**) too; **exits and people** are markers, dragged to move them; **the story's start** is the flag (**Start the story here** writes the scenario's `start`, listing the map in the scenario if it's the campaign's and isn't yet).
  - **A scene's place.** A region that lays its scene's place shows the place over the map at its `worldOrigin`, five feet to a tile, the moment it's selected (and as soon as a selected region comes to lay one): its areas as rectangles, its things where they stand and its people where they start, each named under its marker (**Name the place's things** in the palette turns the names off). Drag a thing, someone or an area's label to move them; select one to edit it in the inspector (as the place editor has it, below). Each edit is written to the place's file. **Hide it** takes the place off the map.
  - **People about at** (in the palette) shows only the people about at an hour.
  - **Resizing** (**S**): drag an edge's handle, or focus it and press **+** or **−**, up to 160 by 120. New tiles are the Erase material. A north or west edge moves the regions, exits and people with their tiles, and what other files say of them: the scenario's start, and the ways from other maps that land here. Cropping asks first, saying what goes; from the keyboard it asks once for an edge, and pressed again while the handle keeps the focus it crops on (unless more than the ground would go).
- **Preview** is the game's own renderer ([client/map/render.ts](../../client/map/render.ts)) on the map as the game builds it, with its decor and the people about at the hour you choose, roofs lifted or not. Tab on the map switches between Paint and Preview.
- **The Map view** has the map's own fields: its title, its id (renamed by asking: it's the file's name, which the scenario, the exits leading here and the start name too), its description, and any key the format doesn't have; its size (a width and a height, applied from its east and south edges, cropping after asking); where the story starts on it (the tile, or **Start the story on this map** at a tile); the ways in from the scenario's other maps (each a link to its map); and the places laid on it, each a link to its region.
- **The Legend, Regions, Exits and People views** each list theirs beside the chosen one's card, with **[+ Add …]** under the list; a card has **Show on the map** (the Paint view, it selected, the view on it).
  - **A legend entry:** its character (renamed by asking: every tile painted with it is written in the new one), its terrain, look (style), height, whether it blocks or is opaque (or as its terrain), roof and roof height, and **[+ Something stands on it]**: the decor's name, glyph, colour, kind, states (chips), look-at text, whether it's in the way, and a stable id for one of a kind. **[+ New entry]** opens the entry's editor (from scratch, or from one of the default legend's entries); **Delete entry…** asks what replaces it where it's painted.
  - **A region:** its name, its id (renamed by asking: unique across the campaign's maps, and game state keys on it), where it is, and its optional parts, each a **[+ …]** until it's there: **[+ Play a scene here]** (the scene, one of the scenario's or a **New scene** made and listed; whether its scene's place is laid here and from which tile; the scene's place, which the scene's file names, chosen or a **New place** made and listed; the trigger and its label), **[+ Shut outside its scene's time]** (what the door says, and the scene whose time opens it), **[+ Locked after its scene]**, **[+ The outside of a scene's place]** and **[+ What its locked doors say]**; its description; and any key the format doesn't have (a migrated region's script `notes`), shown to edit or take out.
  - **An exit:** its label, its tile, the map it leads to (or a **New map**, made and listed, landing in its middle) and the tile it lands on there, with a link to open that map.
  - **Someone about:** their name, glyph, colour, kind, tile, the hours they're about, what they say, their states (chips), and whether they're out of the way. The list is filtered by the hour: who's about in the morning, at night, or at any hour.
- **The Problems view** is the campaign check's problems for this map (and the place shown on it), each taking you to its region, exit, person or legend entry in its view, or opening its file; and says when the map isn't one of the scenario's, or its file isn't `maps/<id>.kmmap`.
- A new map starts from the default legend, the plugin's version 1 palette (grass, dirt, cobbles, boards, water, deep water, bridge, stone and timber walls, a door, a window, a roofed floor, a tree, a fence, stairs) and its clutter (a lamp, a sign, a crate, a barrel, a bench, on cobbles), on a grid of grass.
- The painter uses PixiJS (WebGL) and touches only the tiles a stroke changes: the town (64 by 46, 52 legend entries, 21 regions, 30 people) and a 160 by 120 map paint at once. `canvas.__kmPixi.stats` in the developer tools has its counts. The status line under it is one line whatever it says, so the canvas never changes size under a stroke.

## Version 1 maps

A version 1 map (the plugin's own, a palette id a tile, clutter, spawn points and interactions) opens with what it holds and the offer to migrate it. Migrating writes the file as a map of the format, tile for tile: each palette id and each pair of a palette id and the clutter on it is a legend character (the default legend's, so a migrated map paints like a new one; clutter on anything but cobbles gets a character of its own, its clutter's in capitals); a spawn point becomes the scenario's start if you say so (only on one of the campaign's maps, `maps/<id>.kmmap`), and otherwise a region of a tile named for it; an interaction whose exit led to a map becomes an exit, one whose exit led to a scene a region that plays it, and any other a region of a tile (its event message its description, its script notes kept as `notes`). Its id is its file's name. The original stays in the vault's history (Obsidian's file recovery, and git).

## Files

What follows holds for every file the plugin edits: a scene, the scenario, a map and a place.

- **Exactly the game's file.** A file is opened with the game's parse ([shared/scene/document.ts](../../shared/scene/document.ts) for a scene, [shared/scene/scenario.ts](../../shared/scene/scenario.ts) for the rest) and written back as the same JSON, indented by two spaces with a closing newline, as every file of the campaign is. Opening and saving one with no edit gives the same bytes. An edit changes one value where it is: unknown keys are kept in their places, and a key the format knows that wasn't there goes where the format puts it. An optional field left empty is taken out of the file. A map's grid is written a row at a time: a row nothing was painted on is the same row.
- **Never a file the game can't load.** An edit that would leave a file without its format's shape (a route to a node that isn't there, a fact settled that the scene hasn't got, an exit to no map) is refused with a note, and taking things out takes out what named them (a thing of a place takes what's in it; an area goes only once it's empty).
- **Other files, safely.** An editor that edits another file (the scenario setting an ending's next, a map setting the scenario's start or moving a place's thing) writes it only if it's what the editor read: on disk, or in an editor that has it open, which is given the new text and starts again from it. Otherwise nothing is written and the editor says so. Writes go one after another, and undo spans every file an edit wrote.
- **Version 1 files** (the plugin's old graph files) are never written as they are: a scene or a scenario opens read-only, with a note that the format has moved on, and a map opens with the offer to migrate it, which writes it as a map of the format only when asked.
- A file that isn't one of the game's that the plugin can read opens as an error naming each problem, and its bytes are left as they are. The file is the source of truth: edits go to the file view's save buffer at once, Obsidian writes them, and a save that would overwrite a change made outside the editor is refused.

The scenario journeys: the flow as the files have it; the wiring edited in its owning files (an ending's next set and drawn, a way out and a region in the town's file, a problem appearing in the Problems view) and undone; the scenario's own fields in the Scenario, Files and Quests views, a new map and a new scene made and listed (the scene's card brought into view on the Diagram), and the layout kept. `new-map.spec.ts` writes a new map, its place and the scene laid there from nothing as an author would, every value through a control, twice: the map and the scenario in a 1000px pane and the place and the scene in a 700px one, then the other way round, so each is written at each width: the map made from the Files view, cropped from the Map view, painted with a new legend entry, a region picked with Select that plays a scene made where it's picked and lays a place made the same way, a way to the town and one back, two people by the hour; the place's two areas, three things and two starts (one someone new of the scene's cast); the scene, a path's via picked from the place's things; the scenario wired (the ending's next, the start moved onto the map and back); every Problems view empty, and the files as written (with `KINGMAKER_AUTHORED` set, saved there for the campaign check). `coverage.spec.ts` walks the coverage table's rows the other journeys don't reach through their controls: the scenario's id, the purse, the backstory's docs, a quest renamed across the scenes (and the clerk's quest named first by its onStart), a talk template made where it's picked, the layout forgotten; a legend character and a region's id renamed, a region's optional parts, the start set from the Map view, people by the hour; a thing's id, armour, hit points, quantity and holder, an area renamed, a bare spot of floor, the plan's names. The place journey: a place on its plan, named by its map and region, a thing moved, added and its fields set (its states as chips). `bundle.spec.ts` loads the built bundle as Obsidian loads a plugin (CommonJS, with a mock of the `obsidian` module in a page) and opens every scene, the scenario, every map and every place of the vault in its editor; `KINGMAKER_PLUGIN` and `KINGMAKER_VAULT` point it at an installed copy and its vault.

None of this is the Obsidian desktop app: the host tests and the bundle check stand in for Obsidian's API. `npm run dev` serves the harness (on port 4177) to look at by hand.
